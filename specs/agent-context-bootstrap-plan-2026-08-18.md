# Agent Context Bootstrap Plan - 2026-08-18

- **Status**: Approved by NetOps Lead on 2026-08-18. Executing in current session.
- **Context**: Every knowledge-authoring session begins with the same throwaway discovery calls (`ls -la`, `find knowledge -type f`, `grep "^id:"`, `cat schemas/*`) purely to rediscover the repo layout, the already-allocated `KP-*` IDs, and the frontmatter schema. This burns tokens and turns. Worse, the validator enforces per-type **body** rules that appear in neither the schema nor the skills, and both authoring skills are stale (they instruct `timestamp:` and "OKF v0.1", which fails validation because `generated` is required and `timestamp` is not a schema property). This plan makes the repo self-describing so an agent can start work from two authoritative files.

## Scope Rulings
- **In-Scope**:
  - `tools/okf_manifest.py`: generator producing a machine- and human-readable inventory plus next-free-ID allocation.
  - `MANIFEST.md` (repo root): generated artifact, committed, regenerated by the pre-commit hook.
  - `tools/pre-commit`: regenerate + stage the manifest before running validation.
  - `AGENTS.md` (repo root): static repo map, ID prefix map, frontmatter contract, per-type body rules, authoring workflow.
  - `.agents/skills/knowledge-builder/SKILL.md` and `.agents/skills/junos-okf/SKILL.md`: correct stale OKF v0.1 / `timestamp` guidance; point ID allocation at `MANIFEST.md`.
  - `README.md`: refresh the directory tree.
- **Out-of-Scope**:
  - Changing `schemas/okf-frontmatter-schema.json` or the semantics of `tools/validate_okf.py`. The manifest reports the repo; it does not redefine it.
  - Migrating existing knowledge documents. All 15 currently validate clean.
  - CI configuration; the pre-commit hook remains the enforcement point.

## Scope Ruling: MANIFEST.md lives at the repository root
`tools/validate_okf.py` walks `knowledge/` recursively and requires OKF frontmatter on every `.md` file it finds. A manifest placed under `knowledge/` would therefore have to carry its own `KP-META-*` ID and appear in its own inventory. Keeping the generated artifact at the repo root avoids that recursion, keeps it adjacent to `AGENTS.md` and `README.md` where an agent looks first, and leaves it human-diffable in review.

## Items to Execute
- `tools/okf_manifest.py`:
  - Zero external dependencies; reuses `extract_frontmatter` / `load_yaml` from `validate_okf.py` so manifest and validator never disagree on parsing.
  - Emits: per-directory document tables (path, id, type, title, version), a next-free-ID table per `KP-*` prefix, total counts, and duplicate-ID detection.
  - `--check` flag: regenerate in memory, exit 1 if the on-disk file differs (staleness gate).
- `tools/pre-commit`:
  - Run the generator, `git add MANIFEST.md`, then run the validator as it does today.
- `AGENTS.md`:
  - Directory map and what belongs where.
  - ID prefix to domain table and the "read MANIFEST.md, do not grep" allocation rule.
  - Required frontmatter contract, explicitly noting `generated` is required and `timestamp` is not a schema property.
  - Per-type body rules enforced by the validator but absent from the schema: `JUNOS Base Config` requires a `set` codeblock, `Apstra Configuration` requires a `json` codeblock, `JUNOS Audit` requires `verification_method` and `checks`.
  - Authoring workflow: plan file, commit plan, author, validate, commit.
- Skill corrections in `.agents/skills/knowledge-builder/SKILL.md` and `.agents/skills/junos-okf/SKILL.md`.
- `README.md` directory tree refresh.
